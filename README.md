# dsh-auto-translate-ui

Плагин для DeepSeek Harness (DSH), который переводит на русский (или английский)
**иноязычные элементы интерфейса**, которые сторонние плагины показывают «как есть» —
чаще всего на китайском. Работает и в веб-GUI, и в **Electron-приложении DSH**
(desktop-оболочка грузит GUI по протоколу `dsh-app://app`). Перевод запрашивается у
DeepSeek в максимально экономичном режиме, результат складывается в локальный кэш и
используется в UI.

## Зачем

Многие плагины экосистемы DSH не имеют английской или русской локализации:
их настройки, подписи кнопок, подсказки и уведомления остаются на китайском.
Плагин закрывает этот разрыв: всё, что появляется в интерфейсе на «иностранной»
письменности (китайский, японский, корейский, тайский, арабский и т.д.), переводится
на активный язык интерфейса и запоминается.

## Как это работает

Плагин состоит из двух половин, как и любой GUI-плагин DSH:

* **Хост-половина** (`lib/index.js`, Node) — HTTP-маршруты `/api/dsh-auto-translate/*`,
  вызов модели через `ctx.llm` и файловый кэш в `$DSH_HOME/cache/dsh-auto-translate/`.
* **Клиентская половина** (`lib/client.js`, браузер) — перехват `ctx.locale.translate`,
  наблюдение за DOM и батчинг недостающих строк.

Поток данных:

1. При загрузке GUI клиент забирает снимок кэша (`GET /translations?lang=ru`) — уже
   переведённые строки применяются сразу, без мигания оригиналом.
2. Строки, которые проходят через словари локализации, перехватываются в
   `locale.translate`: если перевод известен, React сразу рендерит перевод.
3. MutationObserver ищет в DOM текст на иностранных письменностях вне областей
   контента: при `scope: 'ui'` (по умолчанию) лента чата, рассуждения модели,
   инструментальные карточки, markdown, код, поля ввода и `[data-no-translate]`
   исключаются; `scope: 'all'` переводит и содержимое разговора.
4. Недостающие строки копятся с задержкой (debounce) и уходят одним `POST /translate`.
5. Хост проверяет кэш, оставшиеся строки отправляет в DeepSeek Flash одной-двумя
   пачками, сохраняет результат и возвращает переводы.
6. Клиент применяет переводы к уже отрисованным узлам DOM и запоминает их;
   повторный рендер сразу получает перевод через обёртку `translate`.

Переводы привязаны к **версиям плагинов**: после обновления плагина его строки
помечаются устаревшими и переводятся заново, остальные остаются в кэше.

## Установка

Плагин ставится в профиль как локальный пакет (пока не опубликован в npm).
Единственная runtime-зависимость — `@deepseek-ai/schemastery` (схема настроек),
поэтому один раз установите зависимости в каталоге плагина:

```powershell
git clone git@github.com:galancev/dsh-auto-translate-ui.git
cd dsh-auto-translate-ui
npm install
dsh plugin --profile desktop add link:(Get-Location).Path
```

`link:` требует абсолютный путь к каталогу плагина — здесь его даёт
`(Get-Location).Path`. Если плагин уже склонирован в другое место, подставьте
свой путь вместо вывода `Get-Location`.

Затем перезапустите DSH. Строка плагина появится в профиле
(`~/.dsh/profiles/desktop/package.json` → `dsh.profile.bundles`) и в списке плагинов.
Настройки — **Settings → Plugins → Auto Translate UI**.

Если нужен другой профиль, замените `desktop` на его имя
(`~/.dsh/profiles/<name>`).

Удаление:

```powershell
dsh plugin --profile desktop remove dsh-auto-translate-ui
```

## Экономичный режим DeepSeek

Запрос к модели спроектирован так, чтобы платить как можно меньше:

| Мера | Что делает |
|---|---|
| `reasoningEffort: 'off'` | полностью отключает рассуждения — для перевода UI они бесполезны |
| `temperature: 0` | детерминированный перевод, одинаковые строки дешевле и стабильнее |
| Батчи | 24 строки / 1200 символов на запрос по умолчанию; однострочных запросов нет |
| Фиксированный system-промпт | префикс запроса совпадает между вызовами и попадает в KV-кэш провайдера |
| Лимит вывода от длины входа | `max_tokens` считается по размеру пачки, а не берётся максимальным |
| Нет истории и инструментов | в запросе только system + один user с JSON-массивом строк |
| Кэш | повторно переводятся только новые/устаревшие строки; снимок кэша отдаётся клиенту |
| Негативный кэш | неудачные строки не повторяются 10 минут (настраивается) |
| Дробление пачки | при `max-tokens`/битом JSON пачка делится пополам, а не переводится целиком заново |
| Идентичные строки | дедуплицируются в пределах запроса и между плагинами (по тексту) |

## Кэш и версии плагинов

Файлы кэша лежат в `$DSH_HOME/cache/dsh-auto-translate/` (по умолчанию
`~/.dsh/cache/dsh-auto-translate/`), по одному на целевой язык:
`translations.ru.json`, `translations.en.json`.

Формат записи:

```json
{
  "src": "保存",
  "dst": "Сохранить",
  "owners": { "@scope/dsh-some-plugin": "1.4.2" },
  "ts": 1760000000000
}
```

* ключ — нормализованный исходный текст;
* `owners` — пакеты-владельцы строки и их версии на момент перевода;
* при следующем обращении запись считается свежей, только если версии всех
  известных владельцев не изменились. Обновился плагин — переводятся только его
  строки;
* строки, которые не удалось привязать к пакету (жёстко зашитые в JSX), кэшируются
  по тексту: если плагин меняет текст, меняется и ключ, поэтому устаревший перевод
  не покажется;
* файл пишется атомарно (tmp + rename), права `0600`, с debounce и дозаписью при
  выгрузке плагина; срок жизни записи — 180 дней (настраивается);
* сброс кэша: `POST /api/dsh-auto-translate/forget` (см. «Диагностика») или удаление
  каталога кэша при остановленном DSH.

Владелец строки определяется так: клиент присылает пространство имён локализации
(`ctx.locale.register('<ns>', …)`), хост один раз сканирует собранные клиентские
бандлы установленных плагинов и строит карту `ns → пакет`, а версию берёт из
`package.json` через сервис `pluginPackages`.

## Настройки

Все поля меняются на странице настроек плагина без перезапуска (volatile-поля):

| Поле | По умолчанию | Назначение |
|---|---|---|
| `enabled` | `true` | главный выключатель |
| `targetLanguage` | `auto` | `auto` — активный язык UI, либо `ru`/`en` |
| `provider` | `auto` | `deepseek-account`, `deepseek-official` или `auto` |
| `model` | `deepseek-flash` | идентификатор модели |
| `maxBatchItems` | `24` | строк на запрос |
| `maxBatchChars` | `1200` | символов на запрос |
| `maxTextChars` | `320` | строки длиннее не переводятся |
| `maxOutputTokens` | `2048` | верхний лимит вывода |
| `requestTimeoutMs` | `45000` | таймаут запроса |
| `debounceMs` | `300` | пауза накопления строк |
| `scope` | `ui` | `ui` — только интерфейс, `all` — включая контент чата |
| `includeScripts` | все | какие письменности считать иностранными |
| `latinDetection` | `false` | считать иностранным и латинский текст с диакритикой |
| `translateAttributes` | `placeholder,title,aria-label,alt` | какие атрибуты переводить |
| `skipSelectors` | чат, код, markdown, поля ввода… | что не трогать |
| `cacheDir` | `''` | переопределение каталога кэша |
| `cacheTtlDays` | `180` | срок жизни записей |
| `maxCacheEntries` | `20000` | предел записей на язык |
| `negativeCacheMinutes` | `10` | пауза перед повтором неудачи |
| `seedOnStart` | `true` | отдавать снимок кэша при загрузке |
| `allowThinkingFallback` | `false` | разрешить провайдеру «думать», если off недоступен |
| `logLevel` | `info` | `off…debug` |

## Приватность

* Переводимый текст отправляется в DeepSeek (ваш аккаунт/ключ, модель Flash).
* По умолчанию переводится только интерфейс: чат, markdown, код и поля ввода
  исключены селекторами; `scope: all` включает и контент.
* Кэш хранится локально, доступен только владельцу (`0600`), наружу ничего не
  отправляется.
* В системном промпте нет путей, имён файлов и содержимого разговора.

## Диагностика

Same-origin запросы к хост-половине (из консоли окна GUI — работает и в браузере,
и в Electron-оболочке):

```js
// состояние: версии плагинов, доступность провайдеров, размер кэша
await (await fetch('/api/dsh-auto-translate/meta')).json()
// конфиг, который видит клиент
await (await fetch('/api/dsh-auto-translate/config')).json()
// сброс кэша обоих языков
await fetch('/api/dsh-auto-translate/forget', {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-dsh-auto-translate': '1' },
  body: JSON.stringify({ all: true }),
})
```

### Electron

Desktop-приложение DSH загружает GUI по внутреннему протоколу
`dsh-app://app/` (а не `file://`): запросы страницы (включая `/plugins/...`
и `/api/...`) проксируются оболочкой на локальный хост DSH с его cookie.
Поэтому относительные `fetch('/api/dsh-auto-translate/...')` плагина работают и в
Electron, без отдельного IPC-моста — это тот же путь, которым пользуются
locale/connection-плагины DSH. Хост-маршруты плагина принимают запросы с
`Origin: dsh-app://app`, с loopback-сокета без Origin и обычные same-origin
запросы браузера; cross-site запросы отклоняются.

## Ограничения

* Языки с латинской графикой (немецкий, польский, французский) без диакритики
  по умолчанию считаются английскими: включите `latinDetection` или добавьте
  нужную эвристику селекторами.
* Жёстко зашитые в JSX строки без пространства имён не привязываются к версии
  пакета (ключ — сам текст); обычно это безопасно, потому что при изменении
  текста меняется ключ.
* Перевод идёт через модель: возможны стилистические огрехи, особенно для
  коротких подписей без контекста. Кэш можно сбросить и перевести заново.

## Разработка

```powershell
# тесты (встроенный node DSH 24.x)
node --test --test-isolation=none "test/*.test.mjs"

# изолированный стенд: поднимает второй dsh web в .verify/ на порту 51999
# (link:-спек должен быть абсолютным: pnpm запускается в каталоге профиля;
#  если 51999 занят или зарезервирован Windows — добавьте --port <свободный>)
node tools/harness.mjs --plugin dsh-auto-translate-ui --plugin-spec "link:$((Get-Location).Path)"
```

Клиентский бандл пишется вручную в формате модульного загрузчика DSH
(`window.__ModuleLoader__.load({ id, factory })`), поэтому шаг сборки не нужен.
